# Frontend Runtime Integration Gate Inventory

Status as of `WO-066`: synthetic/local CR-2 primary UI runtime, Figma handoff inventory, and standalone workflow completion evidence. This document does not claim production launch readiness, formal accessibility certification, HIPAA certification, live PHI processing, live EHR sync, live AI execution, live object storage, claim submission, or autonomous clinical/coding/billing behavior.

The gate requires production-intended browser routes to use typed API clients and persisted backend state. Synthetic local React state is limited to transient control state, Storybook/demo behavior, documented mocks, or route states that are explicitly disabled/deferred. After `WO-064`, the primary AURA Note routes are API-backed primary runtime surfaces; live-vendor behavior remains disabled or represented by documented adapter mocks.

Post-CR4 Figma Make catch-up adds `GET /api/v1/app-shell` as the composite source for the Figma-derived AURA Note shell. `/aura-note` now reads role-scoped navigation, dashboard metrics, notifications, activity, disabled-feature posture, and layout preference metadata from `createAuraNoteApiClient().getAppShell()`. Sidebar collapse and notification drawer visibility remain transient local React state only; production-intended counts, badges, route states, and safety posture are not locally authoritative. The documentation workspace also adds typed note-content/autosave/version APIs: `GET /api/v1/notes/{noteId}/content`, `POST /api/v1/notes/{noteId}/content/autosave`, `GET /api/v1/notes/{noteId}/versions`, and `POST /api/v1/notes/{noteId}/versions/{versionId}/restore`; local editor text is only unsaved form state before the autosave mutation. The schedule route now calls query-aware `GET /api/v1/schedule/appointments`, `GET /api/v1/schedule/appointments/{appointmentId}/workspace-validation`, and `POST /api/v1/schedule/appointments/{appointmentId}/chart-intake-status`; local filter controls are transient only, while filter options, rows, room/location metadata, virtual visit status, chart-intake state, and workspace validation are API-backed. The workspace review panels now call `GET /api/v1/documentation-workspace/appointments/{appointmentId}/transcript/live`, `POST /api/v1/notes/{noteId}/suggestions/{suggestionId}/restore`, `POST /api/v1/notes/{noteId}/visit-selections/{visitSelectionId}/remove`, `POST /api/v1/notes/{noteId}/visit-selections/{visitSelectionId}/category`, and `POST /api/v1/notes/{noteId}/compliance/issues/{complianceIssueId}/actions`; suggestion evidence, selected-code disposition, compliance issue status, and transcript live summaries are API-backed. The Design 2 finalization route now uses `GET /api/v1/notes/{noteId}/finalization` and existing finalization action endpoints to render Design 2 finalization runtime state: stable evidence spans, per-step item statuses, dual editor variants, patient questions, care-plan candidates, patient insight metadata, billing validation detail, and dispatch metadata. The operations route now calls `GET /api/v1/standalone/operations/runtime` for Figma-derived operations analytics, activity, notification, and settings-summary panels while local React state remains limited to tabs, in-progress form values, and button status.

## Required State Vocabulary

Every production-intended route must expose or document these states before launch-candidate readiness is claimed:

- `loading`
- `empty`
- `ready`
- `saving`
- `failed`
- `permission-denied`
- `read-only`

Additional safe states remain allowed where already specified: `blocked`, `warning`, `degraded`, `disabled`, and `demo fixture`.
