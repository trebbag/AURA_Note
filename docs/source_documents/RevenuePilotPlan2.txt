Below is a comprehensive, incremental development plan for RevenuePilot that (1) matches your toolchain (VS Code + GitHub + Copilot/GPT‑5 Pro), (2) keeps every increment deployable and testable from a browser (no or minimal terminal), (3) enforces a server‑side PHI boundary that never sends PHI to AI, and (4) organizes the codebase like a professional application so you can drill down and isolate issues quickly.
Where I reference original, user‑facing features (note editor, live guidance, Beautify, copy/export, admin analytics, privacy‑first), I’m aligning to the attached plan.
0) Architecture & Repo Skeleton (built to isolate problems fast)
Approach: Modular monolith in a monorepo → fast to build, easy to reason about, and ready to be split into services later if needed.
repo/
  apps/
    web/            # Next.js 15 (App Router, RSC); no service worker/offline
    api/            # NestJS (Node 20) modular API
    worker/         # Background jobs (outbox processing, OCR, file indexing)
  packages/
    ui/             # Design system (Figma tokens → components); Storybook sources
    contracts/      # OpenAPI + Zod schemas; typed clients for web
    core-phi/       # PHI entities/services (Postgres+RLS, column encryption)
    core-nonphi/    # Non-PHI domain & analytics views
    ai-gateway/     # De-id pipeline + LLM client (rejects PHI at runtime)
    uploads/        # Patient chart ingest (PDF/image), OCR, parsing, metadata
    rcm-rules/      # Coding/NCCI/MUE/modifier rules engine
    claims/         # 837p builder, 277/835 parsers, tracking
    denials/        # Denial normalization & appeals helpers
    worklists/      # Queues, SLAs, scheduling worklist, status transitions
    analytics/      # KPI queries, “what-if” projections
    security/       # RBAC/ABAC, audit, redaction, crypto helpers
    feature-flags/  # Flag definitions & evaluation
    config/         # Lint, tsconfig, test presets
  infra/
    terraform/      # Cloud infra (VPC, RDS, S3, Secrets, WAF) for HIPAA-ready envs
    github/         # CI/CD workflows, CODEOWNERS, PR/Danger rules
  docs/
    ADRs/           # Decision records
    SCOPE.md        # What Copilot is allowed to touch each milestone
Dependency/PHI rules (enforced with lint rules):
apps/web can import packages/ui and typed APIs from packages/contracts only.
apps/api can import domain packages; only apps/api talks to core-phi.
ai-gateway cannot import core-phi; it only accepts de‑identified DTOs.
No package may log PHI (redaction middleware + “forbidden keys” ESLint rule).
“Find the bug fast” affordances built into the skeleton:
/status page (web & api): health, build SHA, feature flags, and dependency checks.
“Developer Drawer” (web): toggles for Demo Mode/MSW, show request IDs, show API timings, surface last 10 errors (already redacted).
Per‑feature routes (/notes, /finalize, /claims, /coaching) with sub‑routes for each step so you can isolate a broken slice by URL.
Self‑contained Storybook stories for every component/state; visual regression and a11y checks run in CI.
OpenAPI “try it” docs at /api/docs (staging), backed by contract tests; downstream clients won’t compile if contracts drift.
1) Four Major Phases → Thin, Working Increments
Your phases drive scope. Each phase is delivered in small vertical slices that demo in a browser (no terminal), with PR artifacts (Storybook, Playwright HTML, Lighthouse, API docs).
Phase 1 — Core note workflow & patient summary (MVP)
User goal: Complete a note with live guidance, finalize it (Beautify + patient summary + last suggestions), then copy/download/export; staff gets a summary item to act on scheduling.
Slices (each slice deploys & works):
App shell & Demo Mode (MSW mocks), auth stub UI.
Note Editor + Guidance panel (mocked): render static guidance cards.
Live Guidance v1 (server on): non‑PHI abstractions → ai-gateway → suggestions (codes, gaps, public‑health, differentials).
Finalization flow v1: Beautify output preview + patient summary preview; accept/dismiss final suggestions → Sign‑off.
Copy/Download/Export actions (post‑sign‑off).
Summary → Staff Worklist: signed‑off summary logged as a work item to print & schedule follow‑ups.
Upload Patient’s Chart: server‑side file intake (PDF/image), OCR & text extraction (on your servers), context used for guidance/finalization (still de‑identified before AI).
Admin Analytics (non‑PHI): baseline tiles (revenue per visit, code distribution, documentation gaps, denials %, time‑to‑close, public‑health capture).
Security/Baseline in this phase: Identity & tenanting (OIDC), RBAC/ABAC + audit, Postgres RLS, PHI boundary (core‑phi + ai‑gateway), redacted logs, feature flags, Storybook CI.
Phase 2 — Voice transcription sub‑panel
Always‑on transcription drawer with mic controls; snippets paste into the note; structured nuggets enrich server‑side guidance context (de‑identified before LLM).
Add timestamps/section tags (HPI/ROS/Exam/Plan) to improve Beautify + summary fidelity.
Phase 3 — Claims submission & monitoring + scheduling recommendations
Charge capture & validation (rules engine: NCCI/MUE/modifiers) → Clean‑claim builder (837p) → Submission & status tracking (277/835 parsing if connected).
Scheduling recommendations generated from the signed‑off Patient Summary + rules (follow‑ups, labs, referrals) → staff worklists & SLAs with filters/assignment.
Optional clearinghouse/EHR integrations when ready.
Phase 4 — Coaching module
Mine Phases 1–3 signals to surface lagging performance by user/team (missed codes, frequent gaps, denial root causes), targeted micro‑coaching, and what‑if impact modeling.
Expand analytics (provider/service line) and trend views.
